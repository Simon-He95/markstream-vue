## 行为对齐

- ASCII / Intl.Segmenter 分词、稳定的增长词身份、超过四个活跃词时不强行截断。
- 700ms、`cubic-bezier(0.37, 0.55, 0.86, 0.88)`；final 立即停 fade，最终文本与静态参考完全一致。
- 选中活跃词时收到 final，选区保持且最后一截文字立即出现；reduced-motion 回收完成。
- 小尾部直接提交，大积压共用按帧反馈的收尾调度；独立 block final 和父级 final 的组合另有回归测试。

## 如何解读

统一的是动画和收尾语义，不是所有框架都获得同样的帧率。大积压下仍有长任务，尤其旧版 Vue 2.6 的整个文档更新成本较高。12ms 是反馈目标，不能抢占框架一次提交、解析、浏览器布局或 GC。不能据此承诺零掉帧或总 CPU 更低。

完整补齐会延长到数秒；这段时间来自分帧推进积压，而不是继续等待淡入动画。首轮 final 时间不能与一次性同步全部渲染的耗时直接比较。该测试未为每个其他框架建立改动前的同场景基线，因此不声称其总 CPU 或吞吐量提升。

RAF 间隔是响应性代理指标，不是 GPU 掉帧计数。完成检查每 50ms 查询 DOM 文本，其开销包含在数字中；本报告和 Vue 3 trace 基准的输入、测量方法不同，不能交叉作数值对照。1×/4× 各三轮、同输入对照见 [Vue 3 分帧收尾报告](./streaming-finish-budget-results.md)。

## 复现

先构建共享依赖与各框架包，然后运行：

```sh
node scripts/benchmark-streaming-parity.mjs
```

脚本生成 `.tmp/streaming-parity/site/` 并校验真实动画、选区、reduced-motion、文本一致性和首轮补齐；输出含源文件 SHA-256。[完整记录](./streaming-parity-results.json)。
