# 流式结束收束：CPU、布局和绘制验证

后续 [4× CPU 长文本与大包压测](./streaming-finish-cpu4x-results.md) 已发现稳定的长任务和最长约 0.94 秒的回调间隔。下文是小输入测量，不能推广为大积压同步 flush 无卡顿。

2026-11-02，Chrome 156.0.8078.74，1100×900，headless，生产构建，无 CPU 降速。每场景/版本 3 次，正反顺序交错运行，以下为中位数。

## 结论

上一版分词淡入加延迟收尾确实增加了主线程、布局、Paint 和栅格化 CPU 工作。流畅感不能当作性能收益证明。

本次在 block 结束时 flush 队列、取消文字淡入及仍在运行的入场过渡，显著减少了测试输入中的总工作和结束后的等待。收益来自减少中间渲染与结束后的动画工作，并不意味着 700ms 曲线天然比 200ms 更便宜。对仍在持续输出的 block，不承诺无额外成本。

## 测试口径

- `legacy`：提交 `4556e5d6b1ef9bb4476bf983123ac25a3b01b2a9` 的 4 批、200ms 实现。
- `drain`：当前分词实现，在独立测试构建中关闭 final flush、final 文字收束和 final 入场取消，作为延迟收尾对照。库中没有新增实验开关。
- `finish`：当前分词实现，结束时立即完成。
- `off`：当前实现，`fade=false`，包括现有的静态 DOM 和小包直出优化；因此这是整体配置对照，不是单独关闭 CSS 的实验。
- 都启用 `smoothStreaming=true`、设置 `parseCoalesceMs=0`。相同输入和 DOM/RAF 采样代码；测量包含输入、队列排空和动画结束，结束后另保留 100ms 观察窗口。trace 与采样本身也有开销；收尾更长也意味着采样次数更多，CPU 差值不能全部归因于库本身。Paint/Raster 记录另行反映实际渲染工作。
- 主线程为 CDP `TaskDuration`，不是系统 CPU 百分比。Paint 是 renderer 主线程的绘制记录工作，RasterTask 是该 renderer 的栅格化 CPU 工作，**不是 GPU 时间**。不同指标可能嵌套或并发，不能相加作为总 CPU。
- 活跃动画节点每帧采样，包括输入结束后的排空阶段。旧报告只在输入更新时采样，可能低估峰值，不宜直接跨报告比较。
- 长尾的 `finishDelayMs` 从设置 `final` 到 DOM 已完整且无活跃文字 fade；延迟对照每 50ms 查询一次，有该量级的采样误差。新版本在 `nextTick` 返回时已经完成。这个数字不是屏幕像素出现的硬件延迟。

结束后的 Paint 记录次数：密集输入从延迟收尾的 104 次降到 2 次，突发输入从 150 次降到 2 次；剩余绘制用于呈现最终内容。立即完成的主线程范围：密集 155.4–159.5ms，突发 77.7–87.6ms。

当前版本相较关闭 fade，密集输入总主线程约高 6%，突发输入约高 35%；栅格 CPU 也更高。因此不能承诺动画没有成本。各组帧间隔 p95 为 16.7–16.8ms，未记录到长任务，仅适用于本机这些输入。没有测低端机、真实 GPU 时间、电量、多消息同时输出或超大最终文档，不能保证所有设备与输入都会获益。

## 结束语义与验证

- 接入层收到某个文本 block 的 `text_end` 后，将该 block 的 `final` 设为 `true`；库不接管 SSE 事件。不同 block 分别结束。
- Vue 默认 `flushOnFinish=true`，同一次 Vue 更新就提交最后内容并取消淡入。显式 `flushOnFinish=false` 仍可保留排队行为。外部 controller 可调用 `finish({ flush: true })`。
- 原生浏览器验证覆盖已有段落和刚开始入场的段落：final 后无运行中的动画、文字透明度为 1。36 次运行的最终文本均与静态渲染一致、无浏览器异常；立即完成和关闭 fade 两组的 18 次运行在 final 提交时就完整，且没有剩余淡入节点。
- 当前正在选中的文字保持原 DOM 和选区，最后追加的内容通过静态后缀立即显示；释放选区后再合并回收节点。
- 大包立即结束会集中执行一次解析和布局，无法保证物理 0ms 或任意体量都在一帧内完成。

## 复现与原始数据

```sh
node scripts/benchmark-streaming-finish.mjs
```

脚本构建三个独立版本，在端口 4201 临时启动预览后自动关闭。可用 `FADE_BASELINE_REF` 指定旧版提交。每组第一次运行的原始 Chrome trace 保存在 `.tmp/stream-finish-perf/trace-<场景>-<版本>.json`，可导入 DevTools Performance。
