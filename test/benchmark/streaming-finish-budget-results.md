# 分帧 final 收尾：同场景 4× CPU 验证

2026-11-02。Chrome 156.0.8078.74，1100×900，生产构建；四组输入与同步 flush 基线一致。1×/4× 各跑 3 次，顺序交错，共 24 次。

## 结果

最终复测覆盖 24 次运行。其中 22 次 final 窗口没有 Long Task；5 万字符的 4× 场景有 2 次运行出现长任务，共 3 个、最长 68ms。最大回调间隔的中位数由同步基线的 70.7–919.7ms 降至 33.8–59.3ms，单次最坏仍有 87.5ms。不能称为零掉帧，也不能把反馈预算视为硬实时保证。

以下为三次中位数；最大间隔是先取每次运行的最大值，再取中位数。

| 场景（4×） | 原同步提交 ms | 现在停止淡入/启动收尾 ms | 原最大回调间隔 ms | 现在最大回调间隔 ms | 完整补齐 ms | 有长任务的运行：原 → 新 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 2 万字符纯文本末包 | 21.9 | 2.2 | 70.7 | 57.2 | 1755.8 | 3/3 → 0/3 |
| 约 2 万字符历史 + 约 4 千字符增量 | 298.3 | 10.7 | 375.9 | 48.5 | 348.4 | 3/3 → 0/3 |
| 三个约 8 千字符 Markdown 大包 | 502.5 | 6.2 | 531.6 | 33.8 | 2085.6 | 3/3 → 0/3 |
| 约 5 万字符 Markdown 末包 | 771.2 | 3.3 | 919.7 | 59.3 | 5290.5 | 3/3 → 2/3 |

**前两列不是相同完成度的耗时**：旧同步提交返回时已经显示全部内容；新提交返回时只保证停掉 fade 并启动补齐，完整显示时间必须看“完整补齐”。完成状态每 50ms 查询一次，所以补齐时间含最多约 50ms 的轮询误差。

## 实现

- 将传输结束和渲染完成分开：`final=true` 立即结束文字淡入与入场过渡，解析完成态等到队列排空。
- 小尾部直接提交；较长文档的最终语义确认与提交分帧。大积压以 12ms 为反馈目标，结合上一批 Vue 提交及布局耗时调整大小，通常每批 256–1024 个字素。rAF 与后续任务交替执行，避免把解析、DOM 更新和布局挤成同一个长任务。
- 正常流式阶段将同一帧内的 `animationend` 回收合并为一次 Vue 提交，避免每个词都触发一次段落更新。final 时取消这条回收队列，淡入片段先停止动画，再将 DOM 回收放入相同预算队列。保留选区，不重复淡入；完成后的无效状态更新跳过。
- 稳定节点复用渲染绑定和函数 ref；关闭高度测量时，不再逐帧创建再删除无用的版本登记，降低重复工作和分配。
- 对原始源码与 token 可证明最终形态不变的常规段落、标题、列表、闭合粗体/斜体及行内代码，复用最终 AST。恢复标记、HTML、数学、表格、链接和扩展等继续执行权威 final 解析；不牺牲最终文本正确性来跳过校验。
- 保留初始完整内容/历史恢复、SSR、非追加替换的行为；处理隐藏标签页、输入替换和卸载取消。脚注始终留在可变后缀，避免分批插入正文时复制已有脚注。

## 代价与边界

完整补齐更慢，重复的解析/提交/布局也会增加总工作。这是响应性优化，不能等同于总 CPU 或能耗收益。

| 场景（4×） | 原 Layout ms | 新 Layout ms | 原 Paint ms | 新 Paint ms |
| --- | ---: | ---: | ---: | ---: |
| 2 万字符纯文本末包 | 34.0 | 521.8 | 2.0 | 98.2 |
| 约 2 万字符历史 + 约 4 千字符增量 | 43.4 | 51.6 | 7.0 | 32.7 |
| 三个约 8 千字符 Markdown 大包 | 66.5 | 209.8 | 8.2 | 120.6 |
| 约 5 万字符 Markdown 末包 | 97.6 | 587.9 | 4.0 | 277.7 |

12ms 是调度反馈目标，不能抢占浏览器布局、GC、单个复杂组件或自定义解析回调。不可拆分的围栏开头和复杂 final 校验仍可能超预算。这里只验证这四组输入；不保证所有文档、浏览器和机器都没有长任务。

初始已完成快照、历史恢复、`smoothStreaming=false`、调用方直接传入 `nodes`、外部 controller 强制 `finish({ flush: true })` 不经过这条内置收尾队列。

## 测量与正确性

- 使用 CDP `Emulation.setCPUThrottlingRate` 设置 1×/4×；不是 GPU 降速，也不等价于某个低端机型号。仍关闭虚拟化、批量挂载和视口延迟，和基线保持一致。
- 初始历史与静态参考在测量前准备，测量前请求 GC。每帧只记录时间，不扫描 DOM；完成状态每 50ms 读取一次 renderer metrics，其开销也包含在结果中。
- 观测窗口覆盖 `final` 到全部渲染结束，再加两个 RAF 回调和一秒观察期。新窗口比同步基线更长，包含所有分批工作。跨 final 的回调间隔和 Long Task 可能包含最后一个输入 chunk 的工作。
- RAF 回调间隔是渲染器响应性的代理指标，不是 GPU 丢帧计数。Paint 是主线程绘制记录；GPU 时间与电量未测。
- 所有 24 次运行在 final 提交时均无活跃淡入类名；最终文本与静态参考一致，观察结束无运行中的动画，无浏览器异常。
