# 03：修正 Playground 观察面板与完成状态

优先级：合并前。目标是让演示数据解释用户实际看到的行为，不以表面计数证明实例复用或资源清理。

## 当前问题

- `ObservationPanel.tsx` 使用 `createMemo(() => resourceCounts())`，但资源计数来自普通 `Set`，没有响应式依赖，读到的是初始化快照。
- `resourceTracker.ts` 中 `trackSubscription` 无调用者，面板不能据此证明订阅清理。
- `HomePage.tsx` 的 visible/pending/caughtUp 来自传给 renderer 的输入长度，而不是 renderer 内部平滑后的显示状态。
- `rendererContent` 在 `isStreaming=false` 时改读完整 source，Stop/Reset 的显示语义需要与自然完成、暂停分开；这些变化不能误标为 renderer 已追平。
- 当前身份观察主要关注 code block 外壳；外壳相同并不保证内部 editor runtime 没有重建。

## 工作队列

1. 为每个指标写出其含义、来源和更新时机：源文档、已传输文本、已显示文本、队列、传输状态、显示完成状态、应用资源及 renderer/runtime 资源。
2. 让实际跟踪的资源计数可响应更新，或者删除不能准确维护的指标。不要用每帧轮询全 DOM 代替明确的数据通知，也不要无依据扩张为全局资源监控系统。
3. 明确 tracker 的覆盖范围。应用私有 timer/RAF/observer 与包内部 Worker/editor 分开；只有实际接入的订阅才能计数，无法观测的项目标为未覆盖，不显示“0”冒充证明。
4. 决定内部平滑模式的真实可见状态获取方式：优先使用已有公开 controller/状态入口；若当前没有入口，则将面板字段准确标为传输侧数据，平滑后的指标由独立 controller demo 展示。为面板增加包 API 时须先与计划 02 对齐，避免仅为调试污染公共接口。
5. 固定 Start/Pause/Resume/Stop/Reset/自然完成的状态表及显示内容。参照 React 行为；如保留 Stop 显示完整源文档的语义，界面明确说明，不把它当成正常追平。变更既有交互应记录原因并覆盖回归。
6. 增加资源创建/释放与重复进出页面的测试。编辑器创建/销毁计数放在测试或诊断层，展示区无需把所有内部实现细节暴露给用户。

## 验收条件

- 创建、触发、取消和卸载资源后，显示的计数正确变化；未跟踪资源不会显示为已证明无泄漏。
- 暂停不显示为完成，传输结束与平滑追平区分正确；reset 和切换样例不会保留旧任务数据。
- 已显示文本指标有真实来源；如只显示传输数据，字段名称和说明准确。
- 重复进入退出演示后，已跟踪私有资源回到预期基线，其他 renderer 使用的共享资源不被误释放。
- 普通追加的 DOM 身份与 runtime 创建次数由不同断言验证，不互相替代。

运行相关 playground 行为测试与 typecheck，再在浏览器完成一次流式、暂停、恢复、停止、重置及页面往返。范围仅为 Solid playground、必要的观测测试和经计划 02 确认的最小接口调整。
